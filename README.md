# FunPay + Playerok Telegram Bot

Telegram-бот на **aiogram 3** для управления FunPay и Playerok. Конфигурация хранится в PostgreSQL, поэтому проект подходит для Railway, Render, Fly.io, VPS и других Docker-хостингов.

При первом запуске бот предлагает выбрать первую площадку. После подключения обеих верхняя кнопка
главного меню переключает интерфейс между FunPay и Playerok, при этом фоновые уведомления продолжают
работать для обеих площадок и всегда содержат метку источника.

> Проект использует неофициальные FunPay и Playerok API. Изменения сайтов могут нарушить работу
> парсинга. Используйте автоматизацию с учётом правил площадок и только для собственных аккаунтов.

## Playerok

Подключение выполняется в два шага: IPv4 HTTP/HTTPS-прокси, затем полный набор cookie
(`__ddg5_=...; token=...`) либо только значение `token`. Cookie и прокси шифруются тем же
`APP_SECRET`, что и данные FunPay.

Доступны:

- профиль и подробный баланс: общий, доступный, выводимый, замороженный и ожидаемый;
- уведомления о новых сообщениях, сделках, изменениях статусов и отзывах;
- карусель чатов, просмотр последних сообщений, ответы текстом и изображениями, отметка чата прочитанным;
- список исходящих сделок, карточка сделки и ручное подтверждение выполнения с отдельным подтверждением;
- список объявлений и статусов, а также мастер создания черновика: игра → категория → способ получения → опции → обязательные поля;
- ручная и автоматическая публикация до 24 черновиков с бесплатным приоритетом;
- автоответчик с рабочими часами, задержкой, антиспам-интервалом и точными командами;
- автовыдача по объявлению: запас строк через `$product`, безопасное резервирование и выдача в чат сделки;
- отдельный выключенный по умолчанию переключатель «Отмечать выполненным»: после <em>успешной</em> автовыдачи бот переводит сделку в `SENT`;
- независимые настройки уведомлений и переподключение аккаунта.

Playerok проверяется каждые 20 секунд. Автопубликация запускается раз в 5 минут. Создание полностью
нового универсального объявления не автоматизируется, потому что обязательные поля, способы получения,
опции и вложения различаются для каждой категории; бот запрашивает доступные для выбранной категории
данные и создаёт черновик, а публикация остаётся отдельным действием.

Интеграция закреплена на commit `1df7e806` репозитория
[`alleexxeeyy/PlayerokAPI`](https://github.com/alleexxeeyy/PlayerokAPI). Адаптер создаёт отдельный
экземпляр API на пользователя, несмотря на singleton в исходной библиотеке.

## Возможности

- подключение в обязательной последовательности: прокси → `golden_key`;
- шифрование прокси и `golden_key` перед записью в PostgreSQL;
- расширенный профиль: состояние аккаунта и Runner, активные сделки, обычные/валютные лоты, автовыдача, разделы и игры;
- статистика продаж за 24 часа, 7/30/90/365 дней или всё время: заказы, покупатели, выручка, возвраты и популярные лоты;
- подробный баланс по каждой валюте: всего, доступно к выводу и ожидает разблокировки;
- отдельные настройки уведомлений для сообщений, заказов, статусов, отзывов, поднятия лотов и системных событий;
- дополнительные Telegram-группы и каналы для копий уведомлений с проверкой прав администратора;
- ответ покупателю прямо из Telegram-уведомления;
- расширенный автоответчик: шаблон, задержка, повторный интервал, рабочее время и режим «только первый контакт»;
- точные команды с готовыми ответами без учёта регистра, переменными и уведомлением о срабатывании;
- автоматические и ручные ответы на отзывы, отдельный шаблон для каждой оценки от 1 до 5;
- уведомления об отзыве показывают лот, оценку, комментарий и отправленный ответ;
- уведомления о смене статуса заказа показывают название лота;
- карусель последних чатов на inline-кнопках вместо текстового списка;
- красивый просмотр доступной истории чата с дозагрузкой старых сообщений (защитный лимит — 2000 сообщений);
- ручная отправка текста и изображений в чат FunPay;
- просмотр подробной карточки заказа по ID и полный возврат оплаченного заказа с подтверждением;
- загрузка изображения и прикрепление его к существующему лоту;
- автоматическое и ручное поднятие обычных лотов с соблюдением таймера FunPay;
- автовыдача из реальных лотов FunPay: штучные строки через `$product`, выдача количества заказа,
  защита от повторной выдачи, возврат товара в запас при ошибке и отдельные уведомления;
- автоматическое восстановление проданного лота и деактивация лота при пустом запасе с глобальными
  и индивидуальными настройками;
- настраиваемое периодическое обновление сессии («вечный онлайн»);
- плагины формата FunPayCardinal: загрузка `.py` из Telegram, проверка метаданных, включение/выключение, удаление и восстановление из PostgreSQL;
- совместимые хуки событий Cardinal и мост типичных Telegram-обработчиков/inline-клавиатур плагинов;
- восстановление активных подключений после перезапуска контейнера;
- Runner из актуальной ветки FunPayCardinal с корректной остановкой и обновлением сессии.

В исходящих сообщениях, командах, автоответчике и автовыдаче доступны переменные: `$username`, `$message_text`,
`$chat_id`, `$chat_name`, `$date`, `$time`, `$full_time`, `$account_name`, `$account_id`,
`$order_id`, `$order_link` и `$order_title`. Для ответов на отзывы также доступны `$stars`,
`$rating`, `$review_text` и `$review_reply`.

## Плагины FunPayCardinal

В меню «Плагины» есть четыре раздела:

- **Каталог плагинов** — общий каталог официальных расширений и публикаций сообщества;
- **Мои плагины** — все установленные расширения, их настройки, включение и удаление;
- **Загрузить плагин** — установка собственного `.py`-файла;
- **Документация** — интерактивное руководство прямо в Telegram.

Полный машинно-читаемый контракт с точными сигнатурами, ограничениями, готовым каркасом,
примером автоответа на отзыв и чек-листом находится в
[`PLUGIN_DEVELOPMENT.md`](PLUGIN_DEVELOPMENT.md). Этот же файл можно скачать кнопкой
«Документация → Скачать полную документацию» и передать нейросети вместе с заданием на плагин.

### Общий каталог

Каталог хранится в PostgreSQL и общий для всех пользователей одного экземпляра бота. В карточке
публикации видны название, версия, краткое и подробное описание, автор, UUID и число установок.
Перед установкой исходный `.py`-файл можно скачать и проверить. Установка выполняется только после
отдельного предупреждения о полном доступе Python-плагина к процессу бота и FunPay-аккаунту.

Чтобы опубликовать расширение, сначала загрузите его, затем откройте «Мои плагины → нужный плагин →
Опубликовать в каталоге» и отправьте подробное описание длиной 40–2000 символов. Автор публикации
может обновить описание и исходник либо убрать публикацию; уже установленные у других пользователей
копии при этом сохраняются. Один UUID принадлежит одной публикации, поэтому чужую карточку нельзя
перезаписать. Каталог сообщества не модерируется — проверка исходника остаётся ответственностью
устанавливающего пользователя.

В каталоге изначально доступны три официальных расширения:

| Плагин | Что делает |
|---|---|
| AutoLotsPlugin | Показывает состояние лотов, массово активирует и деактивирует обычные и валютные предложения, удаляет обычные лоты с отдельным подтверждением. При удалении валютные предложения деактивируются. |
| Advanced Profile Stats | Статистика за 24 часа, 7/30/90/365 дней или всё время: продажи, возвраты, покупатели, выручка и популярные лоты. Также показывает общий баланс, доступную к выводу сумму и удержание. |
| Status Plugin | Хранит настраиваемый статус продавца. Когда покупатель отправляет в чат FunPay команду `#status`, бот отвечает заданным текстом. |

### Установка своего плагина

1. Создайте одиночный UTF-8 `.py`-файл размером не более 512 КБ.
2. Добавьте обязательные метаданные и канонический UUID версии 4.
3. Добавьте нужные функции в списки `BIND_TO_*`.
4. В Telegram откройте «Плагины → Загрузить плагин», прочитайте предупреждение и отправьте файл документом.
5. После проверки управляйте расширением через «Мои плагины».

Минимальный пример:

```python
NAME = "Hello Plugin"
VERSION = "1.0.0"
DESCRIPTION = "Отвечает на #hello"
CREDITS = "Author"
SETTINGS_PAGE = False
UUID = "замените-на-канонический-uuid4"
BIND_TO_DELETE = None


def on_message(cardinal, event):
    message = event.message
    if str(message).strip() == "#hello":
        cardinal.account.send_message(
            message.chat_id,
            "Привет!",
            message.chat_name,
        )


BIND_TO_NEW_MESSAGE = [on_message]
```

Обязательные поля:

| Поле | Тип | Назначение |
|---|---|---|
| `NAME` | `str` | название в «Моих плагинах» |
| `VERSION` | `str` | версия расширения |
| `DESCRIPTION` | `str` | краткое описание |
| `CREDITS` | `str` | автор или источник |
| `SETTINGS_PAGE` | `bool` | показывать постоянную кнопку собственной страницы настроек |
| `UUID` | `str` | уникальный канонический UUID4 |
| `BIND_TO_DELETE` | функция / `None` | очистка данных при удалении |

Необъявленные списки хуков считаются пустыми.

Если указано `SETTINGS_PAGE = True`, в карточке плагина внутри «Моих плагинов» постоянно
показывается кнопка «⚙️ Настройки» рядом с выключением и удалением. Плагин должен зарегистрировать
Telegram callback-handler для стандартного Cardinal callback `47:<UUID>:<offset>`; при первом
открытии `offset` равен `0`. Для совместимого импорта доступно `from tg_bot import CBT`, где
`CBT.PLUGIN_SETTINGS == "47"`. У выключенного плагина кнопка остаётся видимой, но при нажатии бот
предложит сначала включить модуль.

### Хуки

- жизненный цикл: `BIND_TO_PRE_INIT`, `BIND_TO_POST_INIT`, `BIND_TO_PRE_START`,
  `BIND_TO_POST_START`, `BIND_TO_PRE_STOP`, `BIND_TO_POST_STOP`;
- сообщения: `BIND_TO_INIT_MESSAGE`, `BIND_TO_MESSAGES_LIST_CHANGED`,
  `BIND_TO_LAST_CHAT_MESSAGE_CHANGED`, `BIND_TO_NEW_MESSAGE`;
- заказы: `BIND_TO_INIT_ORDER`, `BIND_TO_NEW_ORDER`, `BIND_TO_ORDERS_LIST_CHANGED`,
  `BIND_TO_ORDER_STATUS_CHANGED`;
- операции: `BIND_TO_PRE_DELIVERY`, `BIND_TO_POST_DELIVERY`,
  `BIND_TO_PRE_LOTS_RAISE`, `BIND_TO_POST_LOTS_RAISE`.

Событийная функция получает `(cardinal, event)`. Обработчики жизненного цикла получают объект
`cardinal`, а `BIND_TO_DELETE` — `(cardinal, callback)`. Доступны `cardinal.account`,
`cardinal.runner`, `cardinal.telegram`, `cardinal.plugins` и `cardinal.MAIN_CFG`.

### Telegram-совместимость

Через `cardinal.telegram.bot` доступны `send_message`, `edit_message_text`,
`edit_message_reply_markup`, `answer_callback_query`, `delete_message`, декораторы
`message_handler` / `callback_query_handler` и методы `register_*_handler`. Поддерживаются
фильтры `commands`, `content_types`, `func`, а также базовые `InlineKeyboardButton` и
`InlineKeyboardMarkup` из `telebot.types`.

Бот поддерживает однофайловый контракт, все 18 имён хуков Cardinal, импорты `cardinal`,
`FunPayAPI` и базовые `telebot.types`. Плагины, которым нужны дополнительные сторонние
Python-пакеты или нестандартные внутренние модули конкретной сборки Cardinal, потребуют добавить
эти зависимости в образ хостинга.

Исходники плагинов хранятся в PostgreSQL и восстанавливаются в `plugins_runtime/` при запуске.
Выключенный плагин остаётся в базе, но его хуки и Telegram-обработчики не выполняются. При удалении
исходник, настройки и обработчики удаляются.

> Плагин выполняет произвольный Python-код с правами процесса бота. Он способен читать окружение,
> обращаться к базе и управлять FunPay-аккаунтом. Устанавливайте только проверенные плагины.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---:|---|
| `BOT_TOKEN` | да | токен Telegram-бота от BotFather |
| `DATABASE_URL` | да | URL PostgreSQL вида `postgresql://user:password@host:5432/db` |
| `APP_SECRET` | рекомендуется | постоянный секрет для шифрования данных; задайте до первого запуска и не меняйте |
| `LOG_LEVEL` | нет | уровень логов, по умолчанию `INFO` |

Если `APP_SECRET` не задан, ключ шифрования выводится из `BOT_TOKEN`. После смены токена старые данные подключения тогда перестанут расшифровываться, поэтому на продакшене задайте отдельный длинный `APP_SECRET`.

## Быстрый запуск

```bash
cp .env.example .env
# заполните .env
docker build -t funpay-telegram-bot .
docker run --env-file .env --restart unless-stopped funpay-telegram-bot
```

Локально без Docker:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export BOT_TOKEN='...'
export DATABASE_URL='postgresql://...'
export APP_SECRET='длинная-случайная-строка'
python bot.py
```

Для PaaS используйте worker-команду `python bot.py`. Веб-порт не требуется: бот работает через long polling.

## Подключение FunPay

1. Откройте `/start`.
2. Отправьте приватный HTTP(S)/SOCKS-прокси, например `http://user:password@host:port`.
3. Отправьте значение cookie `golden_key` авторизованного аккаунта FunPay.
4. Бот проверит оба значения через FunPay, сохранит их только после успешного входа и запустит Runner.

При первом запуске новой версии дополнительные настройки PostgreSQL добавляются автоматически через
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`; вручную пересоздавать базу не нужно.

Сообщения с прокси и `golden_key` удаляются ботом по возможности. Для этого бот должен иметь право удалять сообщения в используемом чате. Не добавляйте бота в публичные группы и не передавайте доступ к нему посторонним.

## Структура

- `bot.py` — aiogram, PostgreSQL, интерфейс, настройки и менеджер фоновых аккаунтов;
- `PLUGIN_DEVELOPMENT.md` — скачиваемый точный контракт и руководство для создания плагинов человеком или нейросетью;
- `plugin_system.py`, `cardinal.py`, `telebot/`, `tg_bot/` — совместимый загрузчик и адаптеры плагинов Cardinal;
- `FunPayAPI/` — API и Runner, взятые из FunPayCardinal и адаптированные для управляемой остановки на хостинге;
- `Dockerfile` / `Procfile` — запуск на контейнерных и worker-хостингах.
